# 0.2.4 manual check

Checklist for 0.2.4: one Aria at a time, and the fixes to the chat features of 0.2.3. Each line
says who verified it:

- **agent**: run by the coding agent, with no sound judged.
- **user**: has to be done by a person with the app in front of them.
- **pending**: not verified by anyone yet. Replace `pending` with `user` (and the date) when you have checked it.

Close every copy of Aria first, including older versions: they do not take part in the check. Back
up your Aria data folder before the first start of a new build.

**0.2.4 has barely been run by hand** (see "What was run on real hardware"). The checks of 0.2.3 in
[music-to-chat-manual-check.md](music-to-chat-manual-check.md) are still pending too.

## What automated tests cover

| Area | What is tested |
|------|----------------|
| One copy at a time | The first claim on a data folder is first; a second claim reaches the first and asks for its window, and so does a third; a request that comes before the window can be woken is kept; the folder is free again once the first is gone; other folders are not held; a holder that does not answer is still counted as running, and the second copy gives up within its wait; the pipe's name is the same for the same folder only; the app turns a request into "show, restore, focus", once per request. These run with real named pipes, on Windows, Linux and macOS in CI |
| Microphone hotkey | Without a second device it leaves the microphone off, says so, and saves nothing; it can always be turned off; with a second device it flips, saves and says "on" or "off" |
| Microphone name | The engine reports the name of the device it opened; the core keeps it while the microphone is open; the player-bar icon's description names it |
| Fallback | With the chosen music device missing and the default being the second device, no copy is made, and an open microphone closes |
| Slow microphone | With a microphone that takes two seconds to open, the music keeps flowing in real time; one turned off while it opens stays closed and is never reported open |
| Screen readers | The microphone volume at 100 % is read as 100, the music volume in the chat at 50 % as 50 |

Not covered by any test: the window really coming forward on screen; the message when the open
copy does not answer; anything audible.
